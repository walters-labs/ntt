# Formal verification

Cryptol/SAW verifies the production Rust forward NTT, inverse NTT, and cyclic
multiplication for these fixed parameter sets:

| Length | Modulus | Root | Input coefficients |
| --- | --- | --- | --- |
| 8 | 17 | 9 | Every `i64` |
| 16 | 17 | 3 | Every `i64` |
| 8 | 289 = 17² | 110 | Every `i64` |
| 256 | 12289 | 8340 | Every `i64` |

There are no coefficient-range preconditions on these public-operation proofs.
Negative coefficients, `i64::MIN`, and `i64::MAX` are included. The scalar
addition/subtraction/multiplication contracts require canonical inputs; the
normalization proof establishes that condition before the transform runs.

Each small case proves seven Rust/MIR contracts: normalization, modular addition,
subtraction, multiplication, and the three full operations. The 256-point case
proves 27 contracts, including reusable butterflies, stages, and slice kernels.
The final operation specifications use independent direct formulas:

- `DFT(a)[k] = sum_j normalize(a[j]) * root^(j*k) mod q`, with bit-reversed output.
- The inverse DFT uses the inverse root, inverse length, and bit-reversed input.
- `product(a,b)[k] = sum_j normalize(a[j]) * normalize(b[(k-j) mod n]) mod q`.

`normalize` is the Euclidean residue of a signed two's-complement word, specified
using Cryptol's signed remainder followed by adjustment of a negative remainder.
The Rust normalization contract checks this for all 64-bit patterns, including
its overflow obligations. The DFT and convolution sums use exact integers.

The transform proofs include parameter validation, twiddle construction, and the
safety obligations generated by the Rust/MIR backend for these calls. Only the
transform parameter sets in the table are proved. General root generation, CRT,
other transform sizes/moduli, constant-time behavior, and surrounding
cryptosystems remain outside this scope.

A separate foundation suite verifies scalar arithmetic for arbitrary valid
moduli, length-one parameter validation, the three larger consumer parameter
tuples, and the finite modular-exponentiation domain used by ML-KEM. See the
coverage below and the [pinned consumer inventory](consumers.md).

## Toolchain

- SAW 1.6 and Z3 on `PATH` (tested with Z3 4.8.14).
- CVC5 on `PATH` (tested with 1.3.1, included in the installed solver bundle).
- Cryptol 3.6.0; SAW imports the `.cry` specification using embedded Cryptol.
- `mir-json` revision `8cbf9af1821075ef47cf784fef78d2650827730d`, schema 13,
  with `cargo-saw-build` on `PATH`.
- Rust `nightly-2026-03-21`, including `rustc-dev` and `rust-src`.
- Python 3 for selecting the MIR artifact from Cargo's build output.
- `SAW_RUST_LIBRARY_PATH` pointing to the translated `rlibs` directory for that
  mir-json revision and host target.

These proofs were run on `aarch64-apple-darwin`. They rely on the MIR frontend,
its translated standard libraries, SAW, Z3, and CVC5. They are not machine-code
proofs.

## Run

From the repository root, with the toolchain environment loaded:

```sh
# Run all four cases.
bash verification/run.sh

# Or select one or more cases.
bash verification/run.sh 8-17
bash verification/run.sh 16-17 8-289
bash verification/run.sh 256-12289

# Build offline when dependencies are already cached.
CARGO_NET_OFFLINE=true bash verification/run.sh

# Next consumer target (not yet in the completed-coverage table above).
# Use a separate build/log directory to preserve earlier transcripts.
NTT_VERIFICATION_TARGET_DIR=target/verification-1024 \
  bash verification/run.sh 1024-12289
```

The runner validates the case names, builds the current library in debug mode
once, and selects the exact MIR artifact reported by Cargo. Each selected case
runs in a separate SAW process with `--detect-vacuity`. A build or proof failure
stops the command. Rust verification actions have ten-minute timeouts; timing
out is a failure. Logs are saved as `target/verification/ntt-<case>.log`, or
under `NTT_VERIFICATION_TARGET_DIR` when set. The 1024-point case is opt-in;
the default cases and their completed-coverage claim are unchanged.

The runner limits SAW's Haskell heap to **6 GiB** by default. Override this with
`NTT_SAW_MAX_HEAP`, using a positive size such as `4096M` or `6G`. This is a heap
limit, not a limit on total process memory or separate solver processes.
Exceeding it fails the run; it does not waive a proof obligation. Direct SAW
invocations need their own limit, for example `saw +RTS -M6G -RTS ...`.

The runner sets:

```sh
export SBV_CVC5_OPTIONS='--lang smt --incremental --nl-cov --solve-bv-as-int=sum'
```

CVC5's [bit-vector-to-integer translation](https://cvc5.github.io/docs/cvc5-1.3.0/options.html)
makes the word/integer representation proofs tractable. It preserves the exact
finite-width semantics, including overflow behavior. Z3 checks the simplified
transform algebra. Direct SAW invocations need the same CVC5 options.

A successful default transform run reports **48 successful MIR proofs**, together with
proved Cryptol lemmas. Each case ends with messages like:

```text
Verified forward NTT for all i64 inputs: 256_12289
Verified inverse NTT for all i64 inputs: 256_12289
Verified cyclic multiplication for all i64 inputs: 256_12289
```

## General arithmetic and consumer foundations

Run the additional suite independently of the transform proofs:

```sh
bash verification/run-foundations.sh

# Or select individual cases.
bash verification/run-foundations.sh arithmetic-general
bash verification/run-foundations.sh parameters mlkem-powers
```

It builds the current Rust source and keeps its MIR and proof transcripts under
`target/verification-foundations/`. It uses the same pinned toolchain, CVC5
options, and vacuity checks as the transform runner. The new suite reports
**139 successful MIR proofs**, comprising 138 crate-function contracts and one
standard-library contract:

| Case | MIR proofs | Claim |
| --- | --- | --- |
| `arithmetic-general` | 6 | Four scalar helpers and both butterflies for every `2 <= p <= i64::MAX` |
| `parameters` | 5 | The `i64::rem_euclid` contract; length-one validation for arbitrary valid `p` and every signed root congruent to 1; acceptance of the three consumer tuples below |
| `mlkem-powers` | 128 | `mod_exp(17,e,3329) = 17^e mod 3329` for every integer `e` from 0 through 127 |

Normalization accepts every signed `i64`. Binary arithmetic requires canonical
inputs `0 <= a,b < p` and proves a canonical output. The specifications use exact
integer modular arithmetic. Both the narrow multiplication path
(`p <= 3037000500`) and the widening `i128` path are covered, including their MIR
overflow and division obligations. The moduli need not be prime or odd.

The two butterfly contracts cover every valid modulus and arbitrary canonical
coefficients and twiddles. They compose the proved scalar modular operations and
establish canonical outputs. They do not assume prime moduli or valid transform
roots, and they do not by themselves prove the stage loops or a full transform.

The parameter tuples `(N,q,root)` are `(1024,12289,10302)`,
`(2048,12289,1945)`, and `(2048,151019521,51689479)`. These proofs check the Rust
validator accepts them; they do **not** prove transforms at those lengths or
general root generation. Length one is a separate general contract because the
existing radix-2 transform specification starts at length two. Other arbitrary
lengths and roots still require general validation proofs.

ML-KEM's three constructors use the 128 exponents in bit-reversed order. The
power proofs cover the actual `ntt::mod_exp` calls, with no assumed arithmetic
overrides. They do not verify the consumer's bit reversal, table construction,
own NTT, or cryptosystem. They are a complete finite-domain claim, not a claim
about all possible arguments to `mod_exp`.

The multiplication proof separates product bounds, signed remainders, narrowing,
and a 256-bit overflow-check identity. Every rewrite is proved. Three proved
SAWCore cast identities match MIR's sign-extension representation to Cryptol's
representation; `parse_core` constructs those expressions without assuming their
correctness. The parameter proof separately verifies the pinned standard
library's `i64::rem_euclid` before reusing that contract.

`tests/consumer_contracts.rs` checks the three current root selections, padded
cyclic-to-negacyclic products against independent schoolbook multiplication, the
ML-KEM powers, and concrete parameter-mismatch witnesses. These are regression
tests, not formal proofs of the consumer adapters. See `consumers.md` for the
source revisions, findings, and remaining integration obligations.

## Files and proof structure

- `NttSpec.cry`: shared direct mathematical specification, length-polymorphic
  formulas for the convolution theorem, and a separate stage model used at
  implementation boundaries. All use the selected instance's modulus.
- `Ntt8.cry`, `Ntt16.cry`, `Ntt8_289.cry`, `Ntt256.cry`, `Ntt1024.cry`: concrete parameters, including inverses.
  Their root and inverse identities are checked as part of each proof run.
- `harness.rs`: fixed-size wrappers calling the existing public Rust APIs and
  copying their results into arrays. Compiled only for tests or `cfg(crux)`,
  which mir-json sets. The transform implementation is the production code.
- `arithmetic.saw`: proofs of the production scalar helpers and result bounds.
  Their verified contracts are reused as function overrides.
- `mul-proof.saw`: proved word/integer multiplication and signed-remainder
  lemmas, composed before checking the Rust multiplication helper.
- `lemmas.saw`: proved representation and modular-arithmetic lemmas.
- `verify.saw`: full-operation proofs for the small cases.
- `butterflies.saw`, `stages.saw`: production butterfly and stage contracts.
- `stage-bounds.saw`: a proved rule for each butterfly's input bounds. The stage
  proofs specialize it to concrete indices and twiddles, then discharge its
  premises from input canonicality. Vacuity and result checks still use Z3.
- `models.saw`, `kernels.saw`: stage-model equivalence to the direct DFT, followed
  by composition of the verified Rust stages into full slice kernels.
- `kernel-bounds.saw`, `pointwise-bounds.saw`: proved bounds rules used for
  inverse scaling and spectral multiplication, preserving the verified stage
  and kernel contracts while avoiding repeated expansion of their expressions.
  Their simplification sets are constructed once and reused across coefficients.
- `pointwise-result.saw`: a proved generic pointwise expansion and native vector
  equality identity, used to match the Rust multiplication result structurally.
- `convolution.saw`: a recursive proof of the convolution theorem by doubling
  through the selected instance's length. The inverse of two is computed from
  its odd modulus; the constituent identities are proved for that instance.
- `vector-proofs.saw`: proved vector-equality splitting rules. Large mathematical
  identities are checked in pieces of at most 64 outputs, covering both halves
  at every split and preserving the original universally quantified statement.
- `bridge.saw`, `compose.saw`: bit-reversal identities and public API proofs,
  including parameter construction and twiddle-table matching.
- `ntt-*.saw`: entry scripts selecting a concrete specification.
- `verify-staged.saw`: common staged-proof driver. Length, modulus, roots,
  convolution depth, and public wrapper names come from the selected instance.
- `ScalarSpec.cry`, `scalar-mul-proof.saw`, `arithmetic-general.saw`: independent
  integer specifications, proved conversion rules, and all-modulus scalar proofs.
- `butterflies-general.saw`: both production butterflies for all valid moduli,
  using the general scalar contracts; included by `arithmetic-general.saw`.
- `parameters.saw`, `mlkem-powers.saw`: the additional parameter and consumer-power
  contracts described above.
- `run-foundations.sh`: a separate build and proof runner for these contracts.
- `consumers.md`: revision-pinned consumer inventory and integration findings.

`value` interprets a canonical 64-bit coefficient as an exact integer. `repr`
reduces an integer modulo q and returns its canonical 64-bit representation.
To simplify the algebra, a proved lemma expresses intermediate reductions as
`x - q*(x/q)`. Proved distributivity rules expand products, letting polynomial
normalization remove multiples of q.

The final algebraic goals treat `value` and `normalize` as uninterpreted
functions after applying the proved conversion lemmas. These goals must hold
for every interpretation, including the actual definitions. No unproved
function contracts, assumed lemmas, or admitted goals are used.

## The 256-point proof

The production loops have private butterfly, stage, and slice-kernel functions.
The public API is unchanged. Each butterfly is proved for arbitrary canonical
coefficients and twiddle values. Each of the eight stages in each direction is
then proved with the concrete 256-point twiddle table. Kernel proofs reuse those
stage contracts and cover normalization of every signed input.

Separately, the stage model is proved equal to the direct forward and inverse
DFT formulas. Multiplication uses a mathematical convolution proof built by
doubling the length from 1 to 256. At each doubling, SAW proves forward/inverse
splitting, inverse linearity and a shift identity, two product identities, and
the even/odd recurrence of the direct schoolbook convolution. Only the already
proved half-size convolution theorem is reused. This avoids expanding the full
three-transform product at once.

The final public-operation proofs reuse the verified kernels and the convolution
theorem. They also check the constructor's actual twiddle tables against the
tables required by the kernel contracts. Thus the intermediate stage model is
connected to the independent final specification. A separate proved identity
shows that the inverse kernel's input normalization leaves the canonical
pointwise products unchanged.

This case takes substantially longer than the small cases. After reusing proved
bounds rules, caching their simplification sets, and simplifying the mathematical
bridge structurally, a complete regression run took about six minutes on the
development machine (previously about 23 minutes). Each stage and kernel must
pass its own proof; a timeout or failed subgoal stops the run. SAW's experimental lemma-composition commands and
its obligation numbering are used by the proof tactics, so the pinned SAW
version matters. A numbering mismatch fails rule application or list lookup;
the tactics do not discard obligations.

## Remaining milestones

The [saved results and restart notes](results/README.md) record the stopping
point, retained transcripts, and the next bounded experiment.

The selected completion target is the **three fixed consumer parameter sets**
below, with arbitrary signed input coefficients at each tuple. Arbitrary
lengths/moduli across the entire generic API are outside this target.
See the [verification roadmap](roadmap.md). The next step is completing the
1024-point proof with the existing Cryptol/SAW approach.

| Milestone | Remaining work |
| --- | --- |
| Consumer transform sizes | Complete `(1024,12289,10302)`, then `(2048,12289,1945)` and `(2048,151019521,51689479)`. Each needs successful stage, DFT-model, kernel, convolution, and public-operation proofs. |
| Parameter generation | Connect the consumers' actual `omega` calls to the roots required by those proofs. Acceptance of a supplied root does not prove root generation. |
| Consumer integration | Fix stale roots after parameter changes and input-dependent padding; prove actual padding, reduction modulo `x^d+1`, and coefficient representation. Pin the resolved dependency versions. |
| Reproducible release | Run the proofs against the exact release source and record toolchain, dependency, and proof results; add an automated verification gate. |

`ntt-1024-12289.saw` is the next proof candidate. Its complete run should produce
31 successful MIR contracts (four arithmetic, two butterfly, twenty stage, two
kernel, and three public-operation contracts), plus the mathematical lemmas.
Creating the script or passing only its stages does not establish the final
transform or multiplication claims. Until the complete run succeeds, 1024 points
must stay out of the completed-coverage table.

The 1024-point arithmetic, butterflies, all stages, direct-DFT models, and slice
kernels have passed. The public forward and inverse transforms have also been
proved for every signed input. Cyclic multiplication remains in progress, so this
tuple is not yet in the table of cases covering all three operations.
The schoolbook-convolution recurrence passed in an isolated check, but the full
mathematical proof timed out in a long-lived session whose memory footprint
reached about 29 GiB. That session has been closed. The next proof-development
step is to complete multiplication with smaller, separately retained lemmas in
a fresh process under the heap limit. A complete 1024-point batch run under that
limit has not yet succeeded; the 2048-point cases should wait for this result.
ML-KEM implements its own NTT; verifying it or a whole cryptosystem is separate.
Functional MIR proofs do not establish constant-time execution or correctness of
compiled machine code.
